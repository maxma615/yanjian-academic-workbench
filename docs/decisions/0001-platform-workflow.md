## 已确定场景和可调整默认值

唯一日常使用者是在读博士的她。应用在一台电脑本地运行，断网、未连接 GitHub、情侣小屋关闭时仍可使用文献、PDF、笔记、研究日志、科研待办、日历、检索与完整备份。无需在线账号，资料不会自动共享到小屋。

| 项目 | 默认值 | 后续调整方式 |
| --- | --- | --- |
| 资料位置 | 目标系统应用数据目录 | 平台定案后明确具体路径；改变根目录不改变资料格式，先校验和迁移 |
| PDF 打开 | 系统默认 PDF 程序 | 由目标系统文件关联决定；无可用打开器时保留附件并提示 |
| 备份和导出位置 | 每次操作由本人选择 | 取消不产生输出，不覆盖未明确选择的文件 |
| 恢复位置 | 本人选择的独立空目录 | 规范化并校验身份、权限与路径边界，完整验证后才切换 |
| 时间 | `Asia/Shanghai` | 带时刻保留明确时区/偏移，纯日期不做时区转换 |
| 数据规模 | 覆盖首版的代表性测试资料 | 获得真实数量后调整性能基线，不等待真实私人资料才开始设计 |
| 文献元信息 | 手工录入 | 不加入 DOI 自动抓取、OCR、AI 或 Zotero 同步 |
| GitHub | 默认关闭 | 桌面设置中填写专用私人仓库与令牌并确认范围；主动同步 |
| 第二台设备 | 首版不承诺完整同步 | M2 只验证允许文本，PDF 缺席显示“附件未在此设备” |

Markdown/JSON 与本机 PDF 是权威资料；SQLite 是可重建索引。单个资料目录只允许一个写入实例，保存、删除、迁移、同步与备份协调使用写入队列。删除操作记录用于中断恢复；备份先取得稳定快照，再归档和复读校验。上述约束已在规格确认，本记录不增加产品范围。

2A 开发适配器只允许受认证的本机 UI 返回用户主动选择的实际目录，并在建立会话时复验规范化路径、目录身份、空目录和权限；业务层不接收任意路径字符串，`displayPath` 不产生权限，归档也不能扩大授权范围。该适配器是 macOS 开发机验证例外，不代表 Windows 11 Electron 原生对话框已经验收。

## 平台候选及依赖

| 候选 | 文档依据与工程代价 | 本项目采用条件 |
| --- | --- | --- |
| Web UI + Tauri | 开发需要 Rust、前端工具链和目标平台依赖；依赖系统 WebView。Windows 开发涉及 MSVC 与 WebView2，Linux 依赖随发行版核查 | 目标系统、架构及安装权限合适，离线运行、文件访问、PDF 打开与中文输入实验通过 |
| Web UI + Electron | 随应用嵌入 Chromium 与 Node.js；系统能力放在主进程的受控接口，官方 `shell.openPath` 可用系统默认方式打开文件 | **已选方向**；待 Windows 11 目标机安装、原生对话框、权限、PDF 打开与中文输入验收 |
| 本地服务 + 系统浏览器 | 本地后端承担主存储、锁和系统文件操作，需决定其打包/启动方式；不能只用浏览器缓存保存资料 | 桌面壳不适合时再评估；验证仅监听 loopback、请求访问控制、端口冲突、服务生命周期与系统 PDF 打开 |

Electron 方向已选，但尚无 Windows 11 实机通过证据，也没有把目标机依赖版本或安装包结果写成已验收。Task 2A 使用 Node 本地服务完成通用工程，Task 2B 已实现 Electron 封装并生成候选 ZIP；Windows 安装验收仍待目标设备；Tauri 和本地服务不作为并行产品实现。单平台原生方案仅在 Electron 无法满足已确认需求时重新评估。

共同的计划依赖为 TypeScript、React、SQLite、Vitest、Testing Library、Playwright；SQLite 的具体适配库、中文检索方法及打包兼容性在选定平台后验证。Playwright 的 UI 测试不能替代原生对话框、文件权限及目标机安装测试。开发工具依赖与使用者运行依赖分别记录，不要求使用者安装完整开发工具链。

Windows 11 的路径适配必须覆盖大小写不敏感比较、保留设备名、非法字符、盘符/UNC 路径、反斜杠和 Unicode 名称冲突。最终验收区分“安装时是否需要网络”和“安装后科研流程完全离线”。依赖版本只在允许工程建立后记录进应用子目录的真实锁文件；不安装未来依赖来为本记录制造版本号。

官方资料（2026-09-23 核对）：[Tauri 前置要求](https://v2.tauri.app/start/prerequisites/)、[WebView2 分发](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)、[Electron 概述](https://www.electronjs.org/docs/latest/)、[Electron 系统文件打开](https://www.electronjs.org/docs/latest/api/shell)。这些资料说明候选能力与依赖，不是本应用测试证据。

## 五个代表性验收样例

以下为待实现的测试场景，不是现有演示数据。未来夹具全部生成在应用测试目录，使用合规 UUID，不需要真实私人资料。

1. **文献与 PDF**：手工录入中文标题、作者和标签，选择带中文及空格路径的 PDF；复制校验后生成引用，系统打开及导出后哈希一致。复制失败不留悬空引用；重启后再次打开。
2. **关联笔记**：为两篇文献创建一篇 Markdown 笔记，输入“消融实验记录”，保存后重启并检索；未知前置元数据往返保留，导出的字节与主文件一致。
3. **同日多篇日志**：同一天建立“实验过程”和“下一步”两篇日志；分别编辑、检索和导出，UUID 不同且互不覆盖。
4. **待办与日历**：维护科研待办、纯日期截止日、全天事件与带时区会议；切换测试设备时区后日期不偏移，月视图和当天列表一致，完成状态重启后保留。
5. **完整恢复**：含上述资料、本机 PDF、删除快照和冲突副本的备份在复读校验后恢复到本人选定的空目录；UI 打开正文和 PDF、重建索引并检索，权威文件路径/字节数/哈希一致。非法归档、取消或权限失败不改变当前资料及用户既有文件。
