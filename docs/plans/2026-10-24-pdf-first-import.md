# 从 PDF 添加文献

用户要求直接导入 PDF，自动读取作者等信息，本人只核对后保存。现有流程要求先创建元信息记录再添加附件，步骤过多。本轮将导入 PDF 作为文献库和概览新增文献的默认入口，保留较轻的手工录入备用入口。延续本地优先、Windows 11 目标和本应用目录所有权；用户已授权直接实现，无需重走设计审批。

## 设计

采用现有 PDF.js 本地读取 PDF 内嵌元信息、首页文字与字体位置，推测标题、作者、年份和可识别 DOI。不会将 PDF 制作软件、创建时间直接当作论文作者或发表年份。无可靠信息时留空，标题可用文件名兜底并注明；扫描件可继续保存并打开原 PDF，但不宣称已 OCR。

用户随后明确：在「资料与设置」集中填写 Base URL、API Key 和模型名，文献元信息识别及全文翻译共用该在线大模型，以 DeepSeek 为例。按此要求，已有配置时在导入前说明发送目的地，选入 PDF 后将提取的首页文字和内嵌候选交给模型识别；每个模型字段需带可核对的原文依据，未知信息留空。配置或网络不可用时保留本地识别结果并说明。这里是根据 PDF 识别信息，不冒充已联网检索出版社数据库。

界面分为选择文件、核对信息两个状态：可拖放或选择单个 PDF，读取期间显示进度反馈；核对页默认只有标题、作者和年份，期刊、DOI、链接在补充信息中。保留首页对照内容、可更换文件、取消、确认保存并打开阅读器。取消识别不创建文献；更换文件废弃旧结果；保存失败保留输入。既有元信息编辑和向既有论文添加附件不受此流程替代。

## 接口与存储

- 新增共享 `paper-import.ts` 数据契约。
- `POST /api/papers/inspect-pdf` 接受 name/base64，返回建议字段、来源、提醒和首页文字；需要本机会话，最多 50 MB；本地解析无持久化、无外网请求，模型阶段遵循下条配置和发送范围。
- 上述识别请求另带 expectedConfig；仅当当前已配置模型与界面快照一致时调用该模型。发送首页文字，不发送整个 PDF；跨窗口设置变更返回 409，模型失败保留可核对的本地结果。取消请求需取消上游模型调用。
- `POST /api/papers/import-pdf` 接受同一 PDF、核对字段、requestId 和当前资料目录身份。单个受写锁保护的操作提交文献信息和附件，成功后才更新索引；稳定 requestId 保证丢失响应后的重试不重复创建。资料目录发生切换时拒绝旧请求。
- PDF 和 metadata 先写入本应用资料目录中的临时区域并校验，最后以目录重命名发布；损坏文件、只读、失败或取消不能产生可见的半篇文献。
- 不更改业务格式、备份/同步规则；复用已有模型配置和加密凭据，新增集中设置界面，不产生第二套密钥存储。
