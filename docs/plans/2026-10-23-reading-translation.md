# 文献阅读内的全文翻译

**Goal:** 按用户本轮纠正，把翻译作为单篇论文阅读的能力，而非独立导航或任务中心。
**Architecture:** 保留本地翻译引擎、任务 JSON、API 和备份规则；新增随包 PDF.js 浏览器原版阅读器。文献打开进入绑定 paperId 的阅读页面，原版 PDF 与文本阅读使用同一页码，翻译属于文本阅读的显示模式。
**Tech Stack:** React / TypeScript / Vite / Electron / 已有 PDF.js。
**Spec:** 根 docs/specs/academic-workbench.md 第 3.5 节及用户 2026-10-23 的最新纠正。用户已要求理解后动手，常规实现不重复索要批准。

## 交互与取舍

Scholaread 官方帮助页 web-faq-3、pc-faq-6、web-faq-4 将全文翻译放在阅读工具栏，提供逐段对照和原文/重排阅读。采用其“阅读中启用翻译”的组织方式，保留研笺本地优先和用户自带 API。

仅把独立页入口移动到文献库仍会迫使用户在阅读与任务中心之间切换，因此本轮实现真正的论文阅读页面。默认展示原版 PDF，文本阅读提供原文、中英对照、仅译文及字号调整；第一次文本阅读只在本地提取，开始模型翻译仍须明确确认地址和模型。旧译本按论文和附件筛选，仅在当前论文里选择；换页不跳失阅读位置。

不实现 Scholaread 全部能力：本轮不加入 OCR、PDF 原位译文重排、引用跳转、在线同步、划词翻译或自动摘要；不把现有分段规则宣称为自研专业模型。

## Global Constraints

- 只修改 academic-workbench 及本应用拥有的根规格/计划；不动情侣小屋、根 PLAN/AGENTS。
- 既有译文 JSON、配置、写锁、备份恢复与凭据边界不变；本轮不改存储格式。
- 读 PDF 不需密钥、不创建翻译任务、不调用外部服务；切换显示已有译文不重译。
- 切换论文/附件不能显示旧请求的结果；恢复工作区后按 dataDirectory + workspaceId + paperId 重新创建阅读组件，避免恢复目录沿用同一 workspaceId 时读到旧状态。
- 原版 PDF 的 worker、字体、CMap、WASM 随包提供，不能依赖 CDN；不执行 PDF 脚本或打开其中的外部地址。
- Windows 11 目标机仍独立验收；当前 macOS 不作为 Windows 已验收证据。

## Review Focus

- 刷新、返回、旧 #translations 链接和缺失论文：应回到正确文献，不静默选错论文。
- 一篇论文多个附件、多篇论文多个译本：列表/迟到请求不得串篇，旧译文须可用。
- 纯扫描页能看原 PDF；文本提取失败不能卡死原版阅读。
- 快速翻页、缩放、切换附件：取消旧渲染，不复用已销毁的 PDF.js canvas/worker。
- 只读实例和无密钥仍能读 PDF/已有译文，不能创建任务或外发。
