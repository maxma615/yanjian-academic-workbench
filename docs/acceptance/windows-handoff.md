# Windows 11 目标机交接

当前状态：尚未在 Windows 11 实机运行。Windows x64 ZIP 是构建候选；NSIS 在 Mac arm64 上未成功构建。以下用于实际验收，不是已通过记录。

## 启动候选包

1. 记录 Windows 11 build、CPU 架构、普通用户安装权限和所用 ZIP 的 SHA-256。本轮只生成 x64 候选，不推定 ARM64/x86 可用。
2. 将 ZIP 完整解压到该用户可写位置，运行 `YanJian Academic Workbench.exe`。ZIP 自带运行时，不需要安装 Node 或启动情侣小屋。包未签名/公证；如组织策略阻止运行，记录实际结果，不自动提权或修改策略。
3. 在“资料与设置”记录实际资料目录，确认位于系统应用资料位置，通常为 `%APPDATA%/YanJian/data/workspace`；确认重启继续使用同一目录。开发目录与安装资料分开。

## 本地验收

使用新建测试资料，不把真实科研资料当故障夹具。每步记录预期、实际结果、版本/截图及失败时保留的位置。

- 输入法与保存：中文 IME 组合输入、粘贴、Ctrl+S、缩放窗口；创建文献、关联笔记、同日两篇日志、待办和跨日/全天日程。退出、断网、重启后逐条读取与搜索。
- 原生文件：选含中文/空格路径的 PDF，取消一次、导入一次，用系统默认程序打开；导出到新路径及已存在文件路径，核对哈希。撤销覆盖不得改变已有文件；无默认 PDF 程序时应提示错误并保留附件。
- 权限与并发：不可写目录、链接/junction、选择后替换目录、并发放入文件；拒绝时不覆盖用户新增内容。另开相同资料实例时不得获得第二个写者。高频恶意替换的原生句柄级安全仍属于未完成的平台专项。
- 完整恢复：备份包含中文、PDF、同日日志、任务/事件、墓碑及冲突历史；选择独立空目录恢复。核对备份清单、每个文件大小/SHA-256、正文、PDF 和索引。恢复后重启仍使用新目录，旧目录保留。取消或恢复失败不能改变活动资料。
- 升级/卸载：先生成并校验完整备份，再安装/升级/卸载/重装；确认旧活动目录、正文、PDF 与指针保持。`deleteAppDataOnUninstall: false` 是配置，只有这一步实测后才能记为通过。

## 在 Windows 构建 NSIS

需要 Node.js 24 或更新版本，命令在应用目录执行。首次拉取开发依赖及构建工具需要网络；安装后的本地科研功能按断网流程另验。

```powershell
npm ci --cache .npm-cache
npm run package:windows
node scripts/verify-desktop-package.mjs --zip release/YanJian-Academic-Workbench-0.1.0-win-x64.zip
```

`package:windows` 会先重新构建 Web 和 Electron，再生成 NSIS/ZIP；不发布、不签名。安装器默认每用户安装、asInvoker，配置为卸载不删资料。只有得到实际 `.exe` 安装器且完成上述检查后，才能将对应条目标记 PASS。

## 可选 GitHub 验收

目前仅模拟仓库通过，没有连接真实账号。真实演练需要本人明确指定专用私人 owner/repo/已存在分支，在桌面确认同步范围并填写令牌。仓库不能含 README、代码等范围外文件；应用会拒绝整批，不会自动清理它们。不得将代码仓库作为私人科研资料仓库。

授权后使用两个独立测试资料目录，验证单边修改、双边冲突、删除/编辑恢复为新条目、断网重试、远端 revision 变化、断开及凭据清除。审计远端只含允许文本；PDF/待办/日程/凭据不得出现。同步设备缺 PDF 应显示“附件未在此设备”。Windows 安全存储与跨设备真实仓库行为只有实测后记为 PASS。
